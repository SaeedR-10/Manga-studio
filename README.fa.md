# استودیوی روایت (Ravayat Studio)

در نسخهٔ ۰٫۱٫۱، ورود رسمی ChatGPT برای تحلیل، انتخاب روش تصویر API یا انتقال دستی و ورود تصویر نتیجه به همان پنل اضافه شده است. راهنمای کار و محدودیت‌ها: [اتصال اشتراک و روش تصویر](docs/chatgpt-plan.md). آزمون این تغییرات: ۱۰۰ آزمون در ۱۶ فایل؛ اتصال واقعی حساب کاربر هنوز آزموده نشده است.

میزکار محلی ویندوز برای نوشتن رمان وب و تبدیل آن به پنل مانگا/مانهوا: نوشتن فارسی،
مرجع قطعی داستان (canon)، کتابخانهٔ مراجع تصویری، ساخت پنل از متن، تولید و اصلاح
تصویر با اتصال واقعی به ارائه‌دهنده، بازبینی، صفحه‌بندی و خروجی.

همهٔ داده‌ها روی همین دستگاه می‌مانند: متن، پایگاه داده، تصاویر و تاریخچه در پوشهٔ
دادهٔ کاربر. هیچ حساب اجباری، سرور مرکزی یا همگام‌سازی ابری وجود ندارد. سرویس‌های
ابر فقط وقتی استفاده می‌شوند که کاربر خودش کلید وارد کرده و درخواست داده باشد.
نوشتن، مدیریت پروژه، کتابخانهٔ مراجع، پنل‌سازی محلی، صفحه‌بندی و خروجی **بدون**
اینترنت و بدون کلید کار می‌کنند.

> نام محصول در `package.json`، `desktop/main.js`، `electron-builder.yml` و عنوان
> صفحه متمرکز است؛ تغییر نام به معماری، نام پایگاه داده یا مسیرها وابسته نیست.

خروجی واقعی مدل معنا دارد.

### چه چیزی در همین ساخت واقعاً اجرا شد

- `npm run build` و `npx tsc --noEmit`: موفق و بدون خطا.
- `npx vitest run`: ۱۱ فایل، ۶۸ تست، همه موفق (بدون شبکه، با پاسخ‌های کنترل‌شده).
- `npm run desktop:build`: نصب‌کنندهٔ `release/Ravayat-Studio-Setup-0.1.0.exe` (۱۲۱ مگابایت) ساخته شد. امضا انجام نشد (گواهی موجود نیست).
- تست دودی بستهٔ بسته‌بندی‌شده (`RavayatStudio.exe --smoke-test`): نتیجه در
  `release/smoke-packaged.json` — RTL، فونت، ساخت پروژهٔ نمونه با ۱۲ پنل، خروجی
  Markdown با UTF-8، نبود کلید در پاسخ‌ها، و `secretStore: credential_manager`.
- مسیر API روی سرور واقعی: پیش‌نمایش «ورودی‌های ارسالی» بدون کلید کار می‌کند و
  تولید تصویر با خطای صریح `no_key` و هزینهٔ «نامشخص» رد می‌شود (بدون درخواست پولی).
- خروجی صفحه: PNG و PDF از رابط کاربر تولید و فایل‌ها بازبینی شدند (شکل‌گیری حروف
  فارسی و بالن درست؛ PDF با هدر `%PDF-1.7` معتبر).
- ماندگاری پس از بستن برنامه: سرور با همان پوشهٔ داده خاموش و دوباره اجرا شد؛
  پروژه، متن صحنه و هر ۱۲ پنل بدون تغییر بازگشتند.
- پشتیبان و بازیابی روی سرور واقعی: بستهٔ پروژه گرفته شد و در رکورد تازه بازیابی
  شد (۱۲ پنل، ۴ موجودیت، ۳ واقعیت)؛ تصویر بازیابی‌شده شناسهٔ تازهٔ خودش را گرفت،
  از `/api/assets/…` با `image/png` سرو شد و ارتباط متن/تصویر حفظ شد.
- بازبینی دوباره روی ساخت تازهٔ تولیدی (`next start` با پوشهٔ دادهٔ خالی): پروژهٔ نمونه
  با ۱۲ پنل ساخته شد (هر ۱۲ پنل به نسخهٔ متن منبع و مکان وصل‌اند، ۶ پنل دیالوگ دارند،
  ۸ پنل شخصیت صریح دارند)؛ در صحنهٔ فلش‌بک واقعیت «زخم» با شروع اعتبار ۲۰۲۶-۰۲-۲۰
  حاضر نبود؛ خروجی Markdown با BOM و متن فارسی درست بود؛ بستهٔ پروژه در رکورد تازه
  بازیابی شد (۲ صحنه، ۴ موجودیت، ۳ واقعیت، ۱۲ پنل با اتصال متن)؛ پشتیبان SQLite با
  `VACUUM INTO` نوشته شد و هیچ کلیدی در پاسخ‌ها نبود؛ درخواست تولید بدون کلید پیش از
  هر فراخوانی شبکه با `no_key` رد شد و پرامپت کامل در تاریخچه ثبت ماند.
- بستهٔ نصب هیچ دادهٔ کاربر، پایگاه داده، تصویر یا فایل `.env` را همراه ندارد؛
  `desktop/prepare.mjs` این موضوع را در پایان بسته‌بندی بررسی و در صورت تخطی
  ساخت را متوقف می‌کند (ردیاب فایل Next کل ریشهٔ پروژه را کپی می‌کند، پس فیلتر
  فهرست‌محور لازم است).

## ۲. پیش‌نیازها

- ویندوز ۱۰/۱۱ (۶۴ بیت) برای اجرای بستهٔ نصبی.
- برای توسعه: Node.js **۲۴** (از `node:sqlite` استفاده می‌شود؛ روی ۲۲ نیاز به
  `--experimental-sqlite` دارد) و npm ۱۱.
- ساخت نصب‌کننده به ابزار اضافی نیاز ندارد؛ `electron-builder` بسته‌های NSIS را
  خودش مدیریت می‌کند.

## ۳. اجرا

```bash
cd ravayat-studio
npm ci                 # نصب دقیق نسخه‌های قفل‌شده
npm run dev            # http://127.0.0.1:3310
```

اجرای دسکتاپ در حالت توسعه:

```bash
npm run desktop:start  # build + prepare + electron
```

ساخت نصب‌کنندهٔ ویندوز:

```bash
npm run desktop:build  # خروجی: release/Ravayat-Studio-Setup-0.1.0.exe
npm run smoke          # اجرای بستهٔ ساخته‌شده با تست دودی (بدون درخواست AI)
```

آزمون‌ها و بررسی نوع:

```bash
npm run typecheck
npm test               # ۶۸ تست در ۱۱ فایل
```

## ۴. داده‌ها، کلیدها و حریم خصوصی

- پوشهٔ دادهٔ پیش‌فرض در نسخهٔ دسکتاپ: `%APPDATA%\Ravayat Studio\data`
  (پایگاه `studio.db`، `assets/`، `exports/`، `backups/`). با متغیر
  `RAVAYAT_DATA_DIR` قابل تغییر است. لاگ‌ها در `…\logs` هستند.
- کلید API فقط از طریق صفحهٔ «تنظیمات اتصال‌ها» وارد می‌شود و در
  **Windows Credential Manager** (سرویس `RavayatStudio`) ذخیره می‌گردد. اگر خزانهٔ
  سیستم در دسترس نباشد، برنامه صریحاً اعلام می‌کند که کلید فقط در حافظهٔ همان اجرا
  می‌ماند. کلید در SQLite، فایل پروژه، خروجی، لاگ یا بستهٔ پشتیبان نوشته نمی‌شود و
  API فقط وضعیت «تنظیم شده / نشده» را برمی‌گرداند.
- سرور داخلی فقط روی `127.0.0.1` با پورت تصادفی گوش می‌دهد؛ پنجرهٔ Electron فقط
  به همان مبدأ اجازهٔ ناوبری دارد و درخواست مجوز مرورگر رد می‌شود.

src/server/repo/         دسترسی داده: پروژه، جهان/مرجع قطعی، مراجع، پنل، AI، صف، صفحه‌بندی

tests/                   تست‌های منطق دامنه (بدون شبکه)

## ۷. محدودیت‌های شناخته‌شده این نسخه

1. **آزمون زندهٔ API انجام نشده است.** آداپتورها بر پایهٔ مستندات رسمی
   (بازبینی ۲۰۲۶-۱۰-۳۰) نوشته شده‌اند و با پاسخ کنترل‌شده تست می‌شوند، اما نخستین
   فراخوانی واقعی باید با کلید خود شما و با آگاهی از هزینه انجام شود.
2. **نصب‌کننده امضای دیجیتال ندارد.** ویندوز ممکن است هشدار SmartScreen نشان دهد.
   رفع: خرید گواهی Code Signing و افزودن `win.certificateFile`/`certificatePassword`
   (یا امضای ابری) به `electron-builder.yml`. نبود امضا به معنی ناممکن‌بودن ساخت
   برنامه نیست؛ بسته ساخته و اجرا می‌شود.
3. تصویر خروجی «تخت» است. لایه‌های متن/بالن در خود برنامه مدیریت می‌شوند؛ فایل
   چندلایهٔ PSD/SVG تولید نمی‌شود و ادعای آن هم نمی‌شود.
4. رندر PNG/PDF صفحه‌ها در مرورگر انجام می‌شود (Chromium حروف فارسی را شکل می‌دهد)،
   پس پیش‌نمایش و فایل نهایی از یک موتور می‌آیند؛ اما PDF بردار نیست و تصویر رستری
   است.
5. بازبینی تصویر یک تصمیم کمکی است، نه تضمین هویت. گزارش «قابل ارزیابی نیست» هم
   ممکن است و همان‌طور ثبت می‌شود.
6. هزینهٔ تصویر مدل‌های GPT Image در مستندات نرخ ثابت هر تصویر ندارد؛ برنامه
   «نامشخص» نشان می‌دهد و فقط مصرف گزارش‌شده توسط سرویس را محاسبه می‌کند.
7. ذخیرهٔ محلی به معنای پردازش کاملاً آفلاین نیست: هر قابلیت AI داده را به سرویس
   انتخاب‌شده می‌فرستد و پیش از ارسال، ورودی و مقصد در رابط نمایش داده می‌شود.

## ۸. نقشهٔ توسعه (در رابط کاربر فعال نیست)

اتصال موتور محلی (ComfyUI)، کنترل ژست/عمق، IP-Adapter، آموزش LoRA، مدل سه‌بعدی
مکان، تولید انبوه پنل، قالب دوم انتشار (صفحه‌ای کامل)، کار تیمی، امضای دیجیتال
نصب‌کننده، آزمون خودکار زندهٔ ارائه‌دهندگان با کلید کاربر.
